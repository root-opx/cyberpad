# File-Linked Notes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a CyberPad desktop note be linked to a `.txt`, `.md` or `.cpnote` file of the user's choosing that stays in step with every edit, and let the user reopen such files (from the app, the command line, or Explorer "Open with").

**Architecture:**
- The .NET host owns every file operation. It uses Windows dialogs, keeps a private `links.json` mapping opaque link IDs to paths, and does atomic writes with external-change detection.
- The page holds only `note.file = {linkId, name, format}`.
- New allow-listed bridge messages connect them, and a named pipe hands paths from a second launch to the running instance.

**Tech Stack:** .NET 8 WinForms + WebView2 (existing), xUnit; vanilla JS with `node:test`.

**Spec:** `docs/superpowers/specs/2026-11-24-file-linked-notes-design.md` (builds on `docs/superpowers/specs/2026-11-23-desktop-app-design.md`).

## Global Constraints

- Formats exactly `.txt`, `.md`, `.cpnote`. Wire names are `txt`, `md` and `cpnote`.
- `.cpnote` content is `{"app":"cyberpad","kind":"note","v":1,"cipher":<envelope>}`, using the note's existing envelope (note AAD `neonpad:v1`).
- A link's format must match the note's encryption state: plain notes ↔ `txt`/`md`, encrypted notes ↔ `cpnote`.
- File size cap on disk: 4 MB (`4L * 1024 * 1024` bytes). Decoded text must be ≤ `LIMITS.body` (1,000,000 chars).
- Bridge `text` fields: ≤ `4 * 1024 * 1024` chars. `suggestedName`: ≤ 120 chars. `checkFiles.linkIds`: ≤ 2000 entries.
- `linkId` is exactly 32 lowercase hex characters (`^[0-9a-f]{32}$`), generated by the host from a CSPRNG.
- Link store: `%LOCALAPPDATA%\CyberPad\links.json`, written atomically after every change, and quarantined if unreadable.
- Temp file for linked writes: `.<name>.cyberpad-tmp-<8 hex>` in the target folder, hidden. Retry on sharing or lock violation exactly as `NoteStore.Save` does.
- Text: accept UTF-8 (with or without BOM) and UTF-16 LE/BE with BOM. Refuse anything else, and any text containing U+0000, with "This file isn't UTF-8 or UTF-16 text."
  - The editor works with `\n`. Remember CRLF when `\r\n` outnumbers lone `\n`, and convert back on write. New files are UTF-8 without BOM, LF.
- External change: compare size and last-write time first, then hash. A hash equal to the last confirmed SHA-256 counts as "ok". Status checks run off the UI thread with a 2 s timeout per file; a timeout means "unknown".
- Silent reload only when the note has no unwritten file changes and no typing in that note for 2000 ms. Otherwise show the conflict bar.
- One file, one note. Duplicating a note drops its link. Backup export and import strip `note.file`. Save as or relink onto a path linked to another note is refused with "That file is already linked to another note."
- Command-line or pipe paths: FIFO queue of at most 20. Pipe `\\.\pipe\CyberPad-<SID>`, current user only, one message of at most 32,767 chars.
  - If the second instance can't hand off within 3 s it shows "CyberPad is already running but not responding." and exits.
- The page never sends or receives a path; it sees file names only. Logs stay content-free. No new dependencies.
- All existing constraints from the desktop plan still hold. Work on branch `feature/desktop-app`.

## Review Focus

1. **File edited in another program while the user is typing in CyberPad.** It must never be overwritten without asking. Pinned by `Write_ChangedElsewhere_ReturnsConflictAndLeavesFile` (Task 2) and `decide: recent typing with a changed file asks` (Task 6).
2. **An encrypted note's plain text must never reach a linked file.** Pinned by `fileTextOf: encrypted note yields cpnote JSON without plaintext` (Task 6) and `validateNote drops a link whose format doesn't match encryption` (Task 5).
3. **Linked file deleted, moved, or its USB drive pulled.** The note keeps its text and the file is not recreated. Pinned by `Write_MissingFile_ReturnsMissingAndCreatesNothing` (Task 2).
4. **A binary, mis-encoded or huge file chosen in Open.** It is refused with the message and nothing is imported. Pinned by `Decode_RejectsInvalidUtf8AndNul`, `Decode_RejectsUtf16WithoutBom` (Task 1) and `ReadNew_OverSizeCap_Throws` (Task 2).
5. **A CRLF or non-ASCII file opened and saved without edits.** It must stay byte-identical. Pinned by `Decode_Encode_RoundTripsCrLfAndBom` (Task 1).

      - a non-rooted path
      - `\\.\` or `\\?\` prefixes
      - an extension outside the three formats (case-insensitive)
    - Otherwise `fullPath = Path.GetFullPath(raw)`.

### Task 2: Link store and linked-file I/O (host)

**Files:**
- Create: `desktop/CyberPad.Desktop/Files/LinkStore.cs`, `Files/LinkedFiles.cs`

**Interfaces:**
- Consumes: `TextCodec`, `DecodedText`, `LinkFormat`, `FilePathPolicy` (Task 1); `AtomicFile`, `StoreException` (existing).
- Produces:
  - `sealed record LinkRecord(string Path, LinkFormat Format, TextEncodingKind Encoding, bool Bom, LineEnding LineEnding, long Size, DateTime MtimeUtc, string Sha256)`. `Sha256` is 64 lowercase hex characters of the file bytes.
  - `sealed class LinkStore`:
    - `LinkStore(string dataDir)`
    - `const string FileName = "links.json"`
    - `void Load()`: an unreadable or invalid file is renamed to `links.unreadable-<yyyyMMddTHHmmssZ>.json` and the store starts empty. Invalid individual records are dropped.
    - `bool TryGet(string linkId, out LinkRecord record)`
    - `string Add(LinkRecord r)`: returns a new 32-hex ID.
    - `void Update(string linkId, LinkRecord r)`
    - `bool Remove(string linkId)`
    - `string? FindByPath(string fullPath)`: ordinal-ignore-case on full paths.
    - `void Prune(IReadOnlySet<string> keep)`
    - Every mutation persists through `AtomicFile.Write`.
  - `enum FileStatus { Ok, Changed, Missing, Unknown }`
  - `enum WriteOutcome { Written, Conflict, Missing }`
  - `sealed class LinkedFiles`:
    - `const long MaxFileBytes = 4L * 1024 * 1024`
    - `(LinkRecord Record, string Text) ReadNew(string fullPath, LinkFormat format)`
      - Throws `StoreException("The file is too large to open.")` above the cap.
      - `.cpnote` is decoded as strict UTF-8 with no line-ending change.
    - `string? ReadCurrent(LinkRecord r, out LinkRecord refreshed)`: returns null if missing.
    - `FileStatus Check(LinkRecord r, out LinkRecord refreshed, TimeSpan timeout)`: size and mtime equal → Ok; otherwise compare the hash. A matching hash means Ok, with a refreshed mtime.
    - `WriteOutcome Write(LinkRecord r, string text, bool force, out LinkRecord updated)`
      - A missing file always returns Missing and nothing is created, even with `force` (the spec forbids recreating files).
      - Without `force`, Changed returns Conflict without writing. With `force` (the user's **Keep mine**), a changed file is overwritten.
      - IO failures throw `StoreException` with a short reason.
    - `const int MaxTextChars = 1_000_000`: for `txt`/`md`, `ReadNew` and `ReadCurrent` throw `StoreException("The file is too large to open.")` when the decoded text is longer. `.cpnote` is bounded by the byte cap only, and the page validates the envelope.
    - `LinkRecord WriteNew(string fullPath, LinkFormat format, string text)`: UTF-8, no BOM, LF; replaces an existing file (the dialog confirmed the overwrite).

### Task 5: Note model and platform API for files (page)

**Files:**

**Interfaces:**
- Produces:
  - **`store.js`:**
    - `validateNote` accepts `file: {linkId, name, format}`:
      - `linkId` matches `^[0-9a-f]{32}$`
      - `name` is a string of 1–255 chars with no control characters, `/` or `\`

  - `fileTextOf(note) → string`: a plain note gives `note.body`. An encrypted note gives `JSON.stringify({ app: 'cyberpad', kind: 'note', v: 1, cipher: note.cipher })`. Throws `FileLinkError` if the encrypted note has no cipher.
